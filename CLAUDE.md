# Walking Hand: agent instructions

Read this before doing any work in this repo. These rules apply to every contributor and every coding agent.

## Project in one paragraph

A MuJoCo "Thing" hand (`models/thing_hand/`) walks on its index and middle fingers. We compare three controllers on the same environment: a fixed-gait impedance baseline, pure RL (`WalkingHand-v0`) and tactile RL (`WalkingHandTactile-v0`), both trained with PPO. The plan, status, open decisions and env changelog are in `roadmap.md`. Setup and env spec are in `README.md`.

## Rules

### 1. Keep `roadmap.md` up to date

- Before starting, read `roadmap.md`, including the **Env changelog** at the bottom, so you know the current env version and open decisions.
- When you finish or change a piece of work, update `roadmap.md` in the same branch: tick checkboxes, add new tasks you discovered, record decisions under the relevant heading. Keep entries short and factual.
- Do not delete other people's tasks or notes. If something looks wrong, add a note instead.

### 2. Never push to `main`

- All work happens on a branch and reaches `main` through a pull request.
- Do not `git push origin main`, do not force-push `main`, and do not merge your own PR without the agreement of another team member.
- Before opening a PR, rebase onto the latest `main` (`git fetch origin && git rebase origin/main`).

### 3. Env changes get their own branch and PR

An **env change** is anything that can change what a policy sees, does or is rewarded for, or how the simulation behaves. That includes:

- `models/thing_hand/` (the hand XML, `build_hand.py`, scenes, keyframes, masses, gains, friction, contacts)
- `walking_hand/` (observations, actions, reward, termination, reset, randomization, pushes)
- `docker/`, `requirements.txt`, `docker-compose.yml` (simulator or library versions)

Anything that only changes how training runs (PPO hyperparameters, training and evaluation scripts, logging, plots) is a **training change**.

Rules for env changes:

1. Make them on a branch named `env/<short-topic>`, separate from any training work. Do not mix env and training changes in one PR.
2. If the change alters behaviour (dynamics, observation, action, reward, termination), bump the env version: register new ids (for example `WalkingHand-v1` and `WalkingHandTactile-v1`) in `walking_hand/__init__.py` and update the README. Pure refactors with identical behaviour keep the version.
3. Add an entry to the **Env changelog** in `roadmap.md`: date, new version, what changed, and what training branches need to do.
4. Run `docker compose run --rm mujoco python -W ignore scripts/check_env.py` and paste its output in the PR description.
5. Title the PR `[ENV] ...` so everyone notices it.

### 4. Training branches follow the latest env

- Training work lives on branches named `train/<name>-<topic>`.
- After any `[ENV]` PR is merged, every open training branch must rebase onto the new `main` (`git fetch origin && git rebase origin/main`) before training further or reporting results.
- Results trained on an older env version are not comparable with newer ones. Record the env id (for example `WalkingHand-v1`) and the `main` commit with every saved model and results file, and retrain or clearly label old results after an env bump.
- Pure RL and tactile RL must always be compared on the same env version with the same settings.

## Working in the repo

- Everything runs in Docker. Build once with `docker compose build`, then:
  - viewer: `docker compose up`
  - shell: `docker compose run --rm mujoco bash`
  - env checks: `docker compose run --rm mujoco python -W ignore scripts/check_env.py`
  - offscreen rendering: add `-e MUJOCO_GL=osmesa`
- The hand XML files are generated by `models/thing_hand/build_hand.py`. Change parameters there and regenerate rather than editing the XML by hand.
- Keep large artifacts (checkpoints, logs, videos, zips) out of git. `.gitignore` already covers `runs/`, `logs/`, `checkpoints/`, `wandb/` and `*.zip`.
- Commit messages: short imperative subject line, then a body that says what changed and why.
